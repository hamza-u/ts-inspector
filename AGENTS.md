# AGENTS.md

Instructions for coding agents (Codex, Cursor, pi, and others) that work in this repository. Read this file before you change anything. Task-specific skills are in [`.agents/skills/`](.agents/skills/README.md).

## What this is

TS Inspector is a browser inspector for MPEG-2 transport streams. `build.py` turns the sources into one HTML file, `dist/ts-inspector.html`. That file runs from `file://` with no server and no network calls. A command-line version, `bin/ts-inspector.js`, runs the same analysis in Node.

Plain JavaScript (ES modules), no bundler, no npm dependencies. Python is only for the build and the fixture generator.

## Layout

| Path | What it holds |
|---|---|
| `src/worker/` | The analysis. Runs in a Web Worker in the page and directly in Node for the command. One file per concern: `psi.js`, `scte35.js`, `tr290.js`, `h264.js`, `hrd.js`, `tstd.js`, and so on. |
| `src/ui/` | The page: `index.html`, `app.js`, charts, export, and the workers for FFmpeg and the WebAssembly tools. |
| `src/report.js` | The HTML report, shared by the page and the command. |
| `bin/ts-inspector.js` | The command-line entry point. |
| `build.py` | Inlines everything into `dist/ts-inspector.html`. |
| `scripts/make_fixtures.py` | Writes `test/fixtures/*.ts`. |
| `scripts/build_wasm.py`, `scripts/wasm/` | Compile CCExtractor, telxcc and libklscte35 to `vendor/<name>/`. Needs Emscripten. |
| `scripts/fetch_ffmpeg.py` | Downloads the FFmpeg core to `vendor/ffmpeg/`. |
| `test/` | `node:test` suites. `test/golden/` holds the expected results for each fixture. |
| `vendor/` | NOTICE and licence files for the WebAssembly programs. The built `.js` and `.wasm` files and `vendor/src/` (upstream clones) are not tracked. |
| `dist/` | Build output. Not tracked. |
| `docs/adr/` | Architecture decision records. |
| `.agents/skills/` | Agent skills for this repository. |

## Commands

```sh
node --test test                  # all tests, about 3 s
python3 build.py --no-gpl         # MIT-only page, about 300 kB
python3 build.py                  # full page; embeds whatever is in vendor/
python3 scripts/make_fixtures.py  # regenerate fixtures after a generator change
node bin/ts-inspector.js FILE.ts  # command-line analysis
```

Tests that need `vendor/` skip when it is absent. CI has no `vendor/`, so a test that needs it must say `{ skip: !HAVE }` or the equivalent.

## Rules

### Build

- The page must not reach the network. No `http://` or `https://` in authored code, no CDN, no web fonts. `build.py` and `test/ui.test.js` both check this.
- `build.py` deletes `import` lines and concatenates files. Keep every import name identical to the export name: `import { a as b }` breaks the build on purpose.
- A new file in `src/worker/` or `src/ui/` must also be added to `WORKER_FILES` or `PAGE_FILES` in `build.py`, in dependency order.
- Do not commit `dist/`. CI builds it.

### Analysis code

- Inputs are untrusted binary files. Check every length and offset against the buffer before you read. A malformed packet must produce an error row, never an exception that stops the run.
- Cite the clause for any check or model (for example "H.222.0 clause 2.14.3.1", "ETSI TR 101 290 5.2.1"). Do not copy text from ISO, ETSI, or SCTE documents into the repository.
- Large captures are the normal case. Keep the per-packet path free of allocation where you can. `test/perf.test.js` guards the throughput.

### Tests

- Write the failing test first. For a new check, add a fixture to `scripts/make_fixtures.py` that triggers it, and a golden file in `test/golden/`.
- When you change a golden file, say in the commit message why the expected value changed.
- Run `node --test test` before you say the work is done, and quote the pass, fail, and skip counts.

### Licences

- Our sources are MIT. See [ADR-0001](docs/adr/0001-mit-licence.md). Apache-2.0 is incompatible with CCExtractor, which is GPL-2.0-only.
- Do not copy code from FFmpeg, CCExtractor, telxcc, libklscte35, or any GPL project into `src/`. Those run only as separate WebAssembly programs from `vendor/`.
- A new third-party program in `vendor/` needs a NOTICE with its source URL, commit, and licence, and an entry in `build.py` `TOOLS` and in the README licence table. It must be compatible with GPL-2.0.
- Anything that can be published must use `python3 build.py --no-gpl`, unless the corresponding source is offered from the same place.

### Private data

- Never put employer names, customer names, internal hostnames, IP addresses, private file paths, or real captures in the repository: code, comments, fixtures, docs, commit messages, or git author fields.
- Fixtures are generated by `scripts/make_fixtures.py`. Use made-up service and provider names.
- To check the built page for names that must not ship, run the tests with `TS_INSPECTOR_DENYLIST="name1,name2"`. Keep that list out of the repository.

### Writing

- Docs and comments: short sentences, active voice, one idea each. Match the style of README.md.

### Commits

- Format: `type(scope): description`.
- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`. No others. Build, CI, and licence changes are `chore`.
- 50/72 rule: subject 50 characters or fewer, then a blank line, then a body wrapped at 72 columns.
- Imperative mood, lower-case description, no full stop.
- The body says why. When `test/golden/` changes, it says why each expected value changed.
- Use the `conventional-commit-review` skill to draft and check the message.

## Skills

Skills live in [`.agents/skills/`](.agents/skills/README.md), one `SKILL.md` per folder. They are adapted from [ECC](https://github.com/affaan-m/ECC) for this project. If a skill and this file disagree, this file wins.

| Skill | Use it when |
|---|---|
| `tdd-workflow` | You add a check or parser, or fix a bug. Fixture and failing test first. |
| `verification-loop` | You are about to say the work is done. |
| `security-review` | You touch code that reads stream bytes or renders stream text. |
| `benchmark` | You change a per-packet path or the page weight. |
| `browser-qa` | You change the page. |
| `accessibility` | You add or change a control, tab, table, or chart. |
| `architecture-decision-records` | You make a decision that is hard to reverse. Write it to `docs/adr/`. |
| `conventional-commit-review` | You write a commit message. |
| `search-first` | You need a new parser, decoder, or tool. Check the licence table first. |
